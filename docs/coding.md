# Coding

## Diretrizes

- Siga o estilo existente do projeto.
- Prefira APIs estruturadas a manipulacao fragil de strings.
- Mantenha mudancas pequenas e orientadas ao escopo.
- Escreva comentarios apenas quando eles evitarem leitura trabalhosa.
- Nao introduza dependencia sem justificativa.
- Nao misture refactor amplo com feature ou bugfix estreito.

## Reutilizacao

Antes de criar algo novo:

- procure componente equivalente;
- confira helpers locais;
- revise bibliotecas ja instaladas;
- avalie recurso nativo da stack;
- escolha a menor solucao que resolva o problema real.

## Commits

Commits devem ser compreensiveis, coerentes e sem arquivos fora de escopo.
